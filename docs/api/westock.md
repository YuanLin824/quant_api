# 证券数据（WeStock）

[← 返回目录](../../API.md)

> 所有接口需要 JWT 认证，请在请求头中携带 `Authorization: Bearer <access_token>`
>
> 基于两个第三方 CLI（经子进程调用，非 HTTP 直连）：
> [`westock-data-clawhub`](https://www.npmjs.com/package/westock-data-clawhub)（单文件 bundle 置于 `src/scripts/`）提供 `search` 与 `minute`；
> 腾讯 Go CLI 提供 `kline`（前者不支持分钟 K 线）

## 重要说明

### 每次请求会启动一个子进程

服务通过子进程调用 CLI，**每次请求约 400ms**（实测），比库调用的接口慢。上游超时上限 15 秒，超出返回 `504`。

### 结果是「表格」结构，列由命令决定

CLI 输出一张扁平表格，**不同命令的列不同**，故响应不固定字段，而是给出 `columns`（列名，有序）与 `rows`（行对象，键为列名）：

| 接口              | 列                                                                                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| `/search`         | `code`、`name`、`type`                                                                                           |
| `/minute`（当日） | `code`、`time`、`price`、`volume`、`amount`                                                                      |
| `/minute`（五日） | `code`、`date`、`time`、`price`、`volume`、`amount`                                                              |
| `/kline`          | `date`、`open`、`last`、`high`、`low`、`volume`、`amount`、`exchange`、`change_pct`（多代码时首列多一个 `code`） |

**所有值均为字符串**，不做数值推断。

### 无结果返回 200 而非 404

查询无匹配时 `rows` 为空数组、`total` 为 0，HTTP 状态码仍是 `200`——这是正常的查询结果，不是错误。

### 与 TDX 接口的区别

本模块**不豁免全局限流**（TDX 因复用长连接而豁免）。每次调用都会 fork 子进程并请求第三方上游。另外价格单位是**元**，而 TDX 是「厘」。

## 证券搜索

按关键词搜索证券代码。

**请求**

```
GET /api/westock/search?keyword=腾讯
Authorization: Bearer <access_token>
```

**查询参数**

| 参数    | 类型   | 必填 | 说明                                                      |
| ------- | ------ | ---- | --------------------------------------------------------- |
| keyword | string | 是   | 搜索关键词，最长 50 字符；不能以 `-` 开头，不能含控制字符 |
| scope   | string | 否   | `stock`（股票）或 `fund`（基金）；不传则两者都返回        |

> ⚠️ CLI 另支持 `--sector`，但实测对所有关键词均无任何输出，功能实际不可用，故本接口不提供。

**响应**

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "keyword": "腾讯",
    "columns": ["code", "name", "type"],
    "rows": [
      { "code": "hk00700", "name": "腾讯控股", "type": "GP" },
      { "code": "hk80700", "name": "腾讯控股-R", "type": "GP" },
      { "code": "usTCEHY.PS", "name": "腾讯控股(ADR)", "type": "GP" }
    ],
    "total": 3
  }
}
```

> `type` 的取值由上游定义，常见：`GP-A`（A股）、`GP`（港股/美股）、`ETF`、`ZS`（指数）、`KJ`（开放式基金）等。
> **不传 `scope` 时结果可能混入指数等非股票标的**，需要精确过滤时请显式指定 `scope=stock`。

**字段说明**

| 字段      | 说明                                     |
| --------- | ---------------------------------------- |
| `keyword` | 回显的搜索关键词（已 trim）              |
| `scope`   | 回显的搜索范围（**未传时该字段不出现**） |
| `columns` | 列名，顺序与 CLI 表格一致                |
| `rows`    | 行数据，键为列名；值一律为字符串         |
| `total`   | 返回行数                                 |

**示例**

```bash
curl "http://localhost:3001/api/westock/search?keyword=银行&scope=fund" \
  -H "Authorization: Bearer <access_token>"
```

**示例：无结果**

```json
{
  "code": 200,
  "message": "获取成功",
  "data": { "keyword": "zzz", "columns": [], "rows": [], "total": 0 }
}
```

## 分时数据

获取当日或五日的分时数据。

**请求**

```
GET /api/westock/minute?code=sh600519&days=5
Authorization: Bearer <access_token>
```

**查询参数**

| 参数 | 类型   | 必填 | 说明                                                                                 |
| ---- | ------ | ---- | ------------------------------------------------------------------------------------ |
| code | string | 是   | 证券代码，**须带市场前缀**（如 `sh600519` / `hk00700` / `pt01801081`）；最长 20 字符 |
| days | number | 否   | 天数：`1` = 当日（默认），`2`~`5` = 五日                                             |

> `days` 上限为 5——实测传入大于 5 时 CLI 也只返回 5 天。

**响应（当日）**

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "code": "sh600519",
    "days": 1,
    "columns": ["code", "time", "price", "volume", "amount"],
    "rows": [
      {
        "code": "sh600519",
        "time": "0930",
        "price": "1257.98",
        "volume": "140",
        "amount": "17611720.00"
      },
      {
        "code": "sh600519",
        "time": "0931",
        "price": "1261.98",
        "volume": "572",
        "amount": "71968937.77"
      }
    ],
    "total": 225
  }
}
```

**响应（五日）**——比当日多一列 `date`：

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "code": "sh600519",
    "days": 5,
    "columns": ["code", "date", "time", "price", "volume", "amount"],
    "rows": [
      {
        "code": "sh600519",
        "date": "20260917",
        "time": "0930",
        "price": "1257.98",
        "volume": "140",
        "amount": "17611720.00"
      }
    ],
    "total": 1293
  }
}
```

**字段说明**

| 字段            | 说明                                           |
| --------------- | ---------------------------------------------- |
| `code` / `days` | 回显的查询参数                                 |
| `columns`       | 列名，顺序与 CLI 表格一致                      |
| `rows`          | 行数据；`date` 为 `YYYYMMDD`，`time` 为 `HHmm` |
| `total`         | 返回行数（五日约 1300 行）                     |

> `price` 单位为**元**（与 TDX 接口的「厘」不同）；`volume` / `amount` 是**当日累计值**，非单分钟增量。
>
> 上例中的 `total` 会随交易时段增长（盘中每分钟新增一行），并非固定值；收盘后当日约 240 行。

## K 线数据

获取 K 线走势，支持 11 种周期（**含分钟**）与复权。

**请求**

```
GET /api/westock/kline?code=sh600519&period=day&limit=240
Authorization: Bearer <access_token>
```

**查询参数**

| 参数   | 类型   | 必填 | 说明                                                                                                |
| ------ | ------ | ---- | --------------------------------------------------------------------------------------------------- |
| code   | string | 是   | 证券代码，**须带市场前缀**；支持逗号分隔多代码（如 `sh600519,hk00700`），总长不超过 200 字符        |
| period | string | 否   | K 线周期，默认 `day`，取值见下表                                                                    |
| limit  | number | 否   | 返回条数，1–1000，默认 240                                                                          |
| fq     | string | 否   | 复权方式：`qfq`（前复权）/ `hfq`（后复权）/ `bfq`（仅部分市场）/ `nofq`（不复权）；不传则由上游默认 |
| start  | string | 否   | 起始日期 `YYYY-MM-DD`；不传时由**上游**取默认值 `1990-12-01`                                        |
| end    | string | 否   | 结束日期 `YYYY-MM-DD`；不传时由**上游**取默认值当日                                                 |

> **日期参数的默认值（由上游施加，本接口不补齐）**：`start` 不传默认为 `1990-12-01`，
> `end` 不传默认为**当日**，即上游实际使用的区间为 `[start ?? 1990-12-01, end ?? 当日]`。
> 本接口**只原样转发**显式传入的日期，不代填另一端。
> `1990-12-01` 只是**参数**默认值，上游实际数据起点约 2006 年（见下文 `limit` 说明）。
> 实测：`start=2024-01-01&limit=1000` 返回 659 根（2024-01-02 ~ 2026-09-18）；
> `end=2024-01-01&limit=240` 返回 2023-01-05 ~ 2023-12-29（取 `end` 之前的 240 根）；
> 两者都不传时区间为 `[1990-12-01, 当日]`，配合 `limit` 即「最近 `limit` 根」。
>
> ⚠️ **分钟周期查历史需显式给出日期区间**：不传日期时上游只返回**当天**的分钟数据
> （不报错，但也拿不到更长历史）。两端都传时**跨度不得超过 5 天**，超出返回 `400`；
> 只传一端时因无法判定跨度，直接交由上游处理。
> （注意：上游 help 写的是「近 1 个月内」，与实际不符——实际按**跨度**判定。）
>
> ⚠️ **`limit` 是从区间「末尾往前」取的条数上限**：`limit` 小于区间实际根数时，拿到的是区间**靠后**
> 的部分，而非靠前的部分。例：`start=2024-01-01&limit=240` 返回的是该区间最后 240 根
> （2025-09-23 ~ 2026-09-18），而**不是** 2024 年初的 240 根——此时它与「完全不传日期」的结果相同，
> 容易误以为 `start` 没生效。要取全区间请把 `limit` 设得足够大（上限 1000）。
>
> **`limit` 上限 1000，拉不满全量历史**：上游数据源起点约 2006 年（连 1991 年上市的 `sz000001`
> 最早也只到 2006-03-08），全量约 4900 个交易日（`sh600519` 4926 行、`sz000001` 4851 行）。
> 1000 根折合：**日线约 4.1 年**，`m5` 约 3.5 个交易日，`m1` 约 1.7 个交易日。
> 需要更长历史时用 `start`/`end` **分段取**，按日期切分多次请求。
>
> ⚠️ **被限流时是「静默截断」而非报错**：实测（直接调 CLI）`--limit 5000` 查 `sh600519` 被限流时
> 返回 `200` 与看似正常的表格，但 `total` 只有 **2494**、最早日期从 2006-04-17 退到 2016-06-14，
> **且没有任何限流提示**（「请求过于频繁」的提示反而少见）。故**不能以「拿到了数据」判断请求成功**：
> `total` 明显小于预期时应稍后重试。需要长历史时建议拉一次并自行缓存。

**周期取值**

⚠️ 分钟周期是 **`m1` / `m5`**（前缀 `m`），**不是** `1m` / `5m`——传错会返回 `不支持的 K 线周期`。

| 类型       | 取值                                     |
| ---------- | ---------------------------------------- |
| 分钟       | `m1`、`m5`、`m15`、`m30`、`m60`、`m120`  |
| 日线及以上 | `day`、`week`、`month`、`season`、`year` |

**响应**

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "code": "sh600519",
    "period": "day",
    "columns": [
      "date",
      "open",
      "last",
      "high",
      "low",
      "volume",
      "amount",
      "exchange",
      "change_pct"
    ],
    "rows": [
      {
        "date": "2026-09-18",
        "open": "1262.99",
        "last": "1257.12",
        "high": "1265.88",
        "low": "1256.1",
        "volume": "24891",
        "amount": "3135850000",
        "exchange": "0.2",
        "change_pct": "-0.7782285435"
      }
    ],
    "total": 30
  }
}
```

**示例：多代码**——`columns` 首列多一个 `code` 用于区分：

```bash
curl "http://localhost:3001/api/westock/kline?code=sh600519,hk00700&limit=2" \
  -H "Authorization: Bearer <access_token>"
```

**字段说明**

| 字段              | 说明                                                       |
| ----------------- | ---------------------------------------------------------- |
| `code` / `period` | 回显的查询参数                                             |
| `fq`              | 回显的复权方式（**未传时该字段不出现**）                   |
| `start` / `end`   | 回显的日期参数（**未传时该字段不出现**，上游自行取默认值） |
| `columns`         | 列名，顺序与 CLI 表格一致                                  |
| `rows`            | 行数据；`date` 在日线为 `YYYY-MM-DD`，分钟线带 `HH:mm:ss`  |
| `total`           | 返回行数                                                   |

> `open` / `last` / `high` / `low` 单位为**元**；`last` 即该周期收盘价。
> `exchange` 与 `change_pct` 的语义由上游定义（`change_pct` 实测为涨跌幅，但精度不稳定）。

**已知限制**

- **`bfq` 仅部分市场支持**：A 股会返回上游错误（`503`），港股正常。
- **分钟周期复权无效**：上游对分钟线强制不复权，此时传 `fq` 不生效。
- **上游有限流**：多数情况表现为**静默截断**（`200` 但数据不全），少数才返回「请求过于频繁」的 `503`——详见上文警告。

**错误响应**

- `400` - 请求参数校验失败（关键词/代码为空、过长、以 `-` 开头，`scope`/`days`/`period`/`fq` 取值非法，`limit` 越界，`start`/`end` 非 `YYYY-MM-DD`）；
  或 `分钟周期的日期跨度不能超过 5 天`（仅在 `start` 与 `end` **都传入**时校验）
- `401` - `访问令牌无效或已过期`（由守卫抛出）
- `429` - 触发全局限流（每 60 秒 60 次）
- `503` - `证券数据组件不可用，请稍后重试`（`src/scripts/` 下的 CLI 组件缺失或无读取权限，可执行 `npm run setup:westock` 获取）；
  或 `证券数据服务调用失败，请稍后重试`；或 `证券数据服务返回异常，请稍后重试`（输出无法解析，如代码不被上游支持、上游限流）
- `504` - `证券数据查询超时，请稍后重试`（上游超过 15 秒未返回）
