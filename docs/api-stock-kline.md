# K 线（StockKline）

[← 返回目录](../API.md)

> 所有接口需要 JWT 认证，请在请求头中携带 `Authorization: Bearer <access_token>`

## 说明

### 数据来源

本模块有**两条互不依赖的取数路径，且用的是两个不同的数据源**：

| 路径     | 接口                                                       | 数据源                      | 说明                                           |
| -------- | ---------------------------------------------------------- | --------------------------- | ---------------------------------------------- |
| **落库** | `POST /api/stock-kline/sync`、`GET /api/stock-kline/stats` | TDX → PostgreSQL            | 每日 16:00 同步全市场**日线**入库              |
| **实时** | `GET /api/stock-kline`                                     | westock CLI（腾讯，子进程） | 单只即时拉取，**不读数据库、不写库**，周期任选 |

> 实时查询**不受**每日同步的时效限制，周期也可任选（落库只有日线）。
> 需要已落库的稳定快照请走落库路径（由 `sync` 写入，目前没有对外暴露的读接口）。
>
> ⚠️ 两条路径的**行情列同名同义**（元 / 手），但**成交额精度不同**：CLI 侧有截断
> （实测同一交易日 `1972730000` vs TDX 的 `1972732160`），**不要拿两者的数据做逐值比对**。

### 数据范围（落库）

A 股全市场日线（沪深北，代码取自 `stock_symbols` 表），**首次回补近两年**，之后每日盘后增量更新。

规模：约 5400 只 × 约 490 个交易日 ≈ **265 万行**。

### 单位

| 字段                              | 单位   | 说明                                          |
| --------------------------------- | ------ | --------------------------------------------- |
| `open` / `high` / `low` / `close` | **元** | 上游以「厘」（元 × 1000）表示，返回前已 ÷1000 |
| `amount`                          | **元** | 同上                                          |
| `volume`                          | **手** | 1 手 = 100 股；**各周期口径一致**             |

> 两条路径的量纲来源不同：**TDX 侧原样返回「厘」**（元 × 1000），由本模块在落库时 ÷1000；
> **westock CLI 侧直接给「元」**。两者在接口层统一为元。
>
> 成交量在 TDX 库内对分钟级另做 ÷100（上游给的是「股」），但**净结果都是「手」**
> —— 实测同日各周期可对齐（某周日线之和 2,891,880 手 vs 周线 2,891,882 手）。

### 定时同步

每天 **16:00（Asia/Shanghai）**自动同步（A 股 15:00 收盘后一小时）：

- **表为空** → 全量回补近两年（每只 800 根，一次请求即可，在上游硬上限内）
- **表非空** → 增量补最新 5 根（多拉几根以自愈「前一日失败或漏跑」的情况）
- upsert 语义：`(code, trade_date)` 冲突时覆盖行情列，值无变化则不写入
- **只保留近两年**：每次同步结束后会**硬删除**早于两年窗口的行（`DELETE ... WHERE trade_date < 两年前`）

> 「过滤」与「删除」是两件事：拉取时的 `since` 过滤只能挡住**本次拉回来的**超期数据，
> 把库里已随日历滑出窗口的旧数据清掉，靠的是每次同步后的硬删除。
> 删除是**物理删除**（本表无软删除），删除条数见响应中的 `purged`。

**取数参数**：每只请求 `count=800` 根（TDX 的硬上限）——**TDX 无法按日期限定区间**
（它的 `start` 是「从最新往前倒推的偏移量」而非日期），故多取一些再按两年窗口自行裁剪。

**请求节奏**：逐只经 TDX 长连接拉取（单次实测约 20ms），
并在相邻两次请求之间**加 1 秒间隔**（上游是公开的行情服务器，不宜高频拉取）。

> 因此全市场约 5400 只需 **约 90 分钟**（不加间隔时约 2 分钟）。每日盘后的增量任务
> 同样要遍历全市场，故每次都会跑满这个时长（16:00 启动，约 17:30 结束）。

> **前置依赖**：股票代码来自 `stock_symbols` 表，需先执行过 `POST /api/stock-symbols/sync`（每日 08:00 自动跑）。

## 手动触发同步

**请求**

```
POST /api/stock-kline/sync
Authorization: Bearer <access_token>
Content-Type: application/json

{ "mode": "full" }
```

**请求体**

| 字段 | 类型   | 必填 | 说明                                                                        |
| ---- | ------ | ---- | --------------------------------------------------------------------------- |
| mode | string | 否   | `full`（近两年）/ `incremental`（最新几根）；**不传则表空走全量、否则增量** |

**响应**

```json
{
  "code": 200,
  "message": "同步完成",
  "data": {
    "mode": "full",
    "total": 5390,
    "succeeded": 5388,
    "failed": 2,
    "rows": 2638120,
    "purged": 240,
    "durationMs": 118000,
    "errors": ["sh600xxx: Request timeout"]
  }
}
```

**字段说明**

| 字段                             | 说明                             |
| -------------------------------- | -------------------------------- |
| `mode`                           | 实际执行的模式                   |
| `total` / `succeeded` / `failed` | 待同步 / 成功 / 失败的股票数     |
| `rows`                           | 写入的行数                       |
| `purged`                         | 硬删除的超期行数（早于两年窗口） |
| `durationMs`                     | 耗时（毫秒）                     |
| `errors`                         | 失败明细（最多 20 条）           |

> 单只股票失败不中断整体（记录后继续）。
>
> ⚠️ 该接口**耗时约 90 分钟**（全市场串行 + 每只间隔 1 秒），调用方**务必放宽客户端超时**，
> 否则会看到连接超时而服务端仍在跑。

**错误响应**

- `400` - `mode 必须是 full/incremental`
- `401` - `访问令牌无效或已过期`（由守卫抛出）
- `409` - `同步任务正在执行中，请稍后再试`（上一次未结束）
- `429` - 触发全局限流（每 60 秒 60 次）
- `503` - `标的代码表为空，请先执行 POST /api/stock-symbols/sync 同步 A 股代码`

## 实时查询某只股票的 K 线

数据源是 **westock CLI**（腾讯 Go CLI，经子进程调用），即时拉取、**不读数据库**
（见[数据来源](#数据来源)）。

**请求**

```
GET /api/stock-kline?code=sh600036&period=m60&fq=nofq&start=2026-09-15&end=2026-09-18&limit=100
Authorization: Bearer <access_token>
```

**查询参数**

| 参数     | 类型   | 必填 | 说明                                                                |
| -------- | ------ | ---- | ------------------------------------------------------------------- |
| `code`   | string | 是   | 带市场前缀的代码，如 `sh600036`；最长 20 字符                       |
| `period` | string | 否   | K 线周期，取值见下表；默认 `day`                                    |
| `fq`     | string | 否   | 复权方式 `qfq`/`hfq`/`bfq`/`nofq`；**不传则由上游取默认（前复权）** |
| `start`  | string | 否   | 起始日期 `YYYY-MM-DD`；**默认 `1990-07-31`**（即全部可得历史）      |
| `end`    | string | 否   | 结束日期 `YYYY-MM-DD`；不传则由上游取当日                           |
| `limit`  | number | 否   | 返回条数，1–1000，默认 240（按时间**降序**）                        |

### 复权

| `fq`   | 含义     | sh600036 在 2020-06-30 的收盘（实测） |
| ------ | -------- | ------------------------------------- |
| 不传   | 上游默认 | **22.02** —— 与 `qfq` 输出逐字节相同  |
| `qfq`  | 前复权   | 22.02                                 |
| `hfq`  | 后复权   | 147.11                                |
| `nofq` | 不复权   | 33.72                                 |

- **不传即前复权**，这是前置依赖：前复权价会随新的分红除权**回溯变动**，同一段历史
  在不同时间查到的数值可能不同 —— 需要稳定可比的历史请显式传 `nofq`。
- ⚠️ **`bfq` 对 A 股会报错**（上游 `service error`），接口表现为 `503`；港股正常。
  与 `nofq` 的区别是后者的别名语义，本接口保留该取值仅为与 CLI 对齐。
- ⚠️ **与落库路径的数值不可比**：`sync` 走 TDX 存的是**不复权**价，而本接口默认前复权。

### 区间与 limit 的语义

`[start, end]` 限定取值区间，而 **`limit` 取的是该区间「尾部」的 N 根**（区间内最新的一批），
**不是**从 `start` 往后数。要取某段早期数据，把 `end` 也一起限定：

```
# 取 2020 年上半年的最后 3 根，而不是 2020-01-01 之后的头 3 根
GET /api/stock-kline?code=sh600036&start=2020-01-01&end=2020-06-30&limit=3
→ 2020-06-30 / 2020-06-29 / 2020-06-24
```

> `limit` 是**上限而非保证**：上游会静默少返回（实测同一个 `--limit 5000` 的请求只回了
> 2494 行，且无任何限流提示）。故选到了多少根以响应为准，不要假定等于 `limit`。
> DTO 另挡住越界值，服务层再做一次 `Math.min` 兜底。

### 周期取值与时间字段

取值与 CLI 的 `--period` 一致，**分钟级的前缀是 `m` 而不是后缀**（`m1`，不是 `1m`）。

| `period` | 周期     | 时间字段格式       | `limit=1000` 实测（sh600036，2026-09-19）   |
| -------- | -------- | ------------------ | ------------------------------------------- |
| `m1`     | 1 分钟   | `YYYY-MM-DD HH:mm` | 241 根 —— 仅最近一个交易日（09:30 ~ 15:00） |
| `m5`     | 5 分钟   | `YYYY-MM-DD HH:mm` | 48 根 —— 同上，一个交易日                   |
| `m15`    | 15 分钟  | `YYYY-MM-DD HH:mm` | 16 根 —— 同上                               |
| `m30`    | 30 分钟  | `YYYY-MM-DD HH:mm` | 8 根 —— 同上                                |
| `m60`    | 60 分钟  | `YYYY-MM-DD HH:mm` | 4 根 —— 同上                                |
| `m120`   | 120 分钟 | `YYYY-MM-DD HH:mm` | 2 根 —— 同上                                |
| `day`    | 日       | `YYYY-MM-DD`       | 1000 根 —— 回溯至 2022-08-08（约 4 年）     |
| `week`   | 周       | `YYYY-MM-DD`       | 262 根 —— 回溯至 2021-08-06（约 5 年）      |
| `month`  | 月       | `YYYY-MM-DD`       | 123 根 —— 回溯至 2016-07-29（约 10 年）     |
| `season` | 季       | `YYYY-MM-DD`       | 41 根 —— 回溯至 2016-09-30（约 10 年）      |
| `year`   | 年       | `YYYY-MM-DD`       | 10 根 —— 回溯至 2017-12-29（约 10 年）      |

- **分钟周期不传日期时只给最近一个交易日**：即使 `limit=1000`，`m1` 也只回 241 根。
  要取历史某天，需**同时**传 `start` 与 `end`（跨度 ≤ 5 天）。
- ⚠️ **分钟周期别只传 `end`**：`start` 会被补成默认的 `1990-07-31`，与 `end` 一起触发跨度校验
  → `400 分钟周期的日期跨度不能超过 5 天`。（只传 `start` 不触发校验，CLI 仅在两端都给时才判定。）
- **实际返回条数由上游数据深度决定，可能远小于 `limit`**（见上表）。
- ⚠️ **`year` 传大 `limit` 会触发上游报错**：实测 `limit=1000` 时上游返回
  `[code=1620053001] service error`，接口表现为 `503`；`limit=100` 及以下正常。
  这是**已知取舍**：不对 `year` 单独压上限，`limit` 已有 1–1000 的全局上界，调用方按需调小即可。
- **分钟级的时间精确到分**：CLI 输出带秒（`2026-09-18 15:00:00`），接口统一截到 `HH:mm`。
  若也只取到日，同一天的 241 根 1 分钟线会得到**完全相同**的标识。
- **周/月/季/年线的时间是周期内最后一个交易日**，不是自然周/月初。
- **日线的时间是 `15:00` 对应的日期**，不代表已收盘。

**响应**

```json
{
  "code": 200,
  "message": "获取成功",
  "data": [
    {
      "code": "sh600036",
      "time": "2026-09-18",
      "open": "40.53",
      "high": "40.92",
      "low": "40.43",
      "close": "40.59",
      "volume": "485204",
      "amount": "1972730000"
    }
  ]
}
```

分钟级（`period=m1`）的时间字段带时分：

```json
{ "code": "sh600036", "time": "2026-09-18 15:00", "open": "40.66", "close": "40.59", "...": "..." }
```

> 数值字段一律为**字符串**（CLI 输出的原样透传），避免经过 JS number 丢精度。
> 查询无结果时返回空数组。

**错误响应**

- `400` - 参数校验失败，含：
  - `code` 为空或过长、`limit` 越界
  - `period 必须是 m1/m5/m15/m30/m60/m120/day/week/month/season/year 之一`
  - `fq 必须是 qfq/hfq/bfq/nofq 之一`
  - `start` / `end` 格式必须为 `YYYY-MM-DD`
  - 未定义的查询参数（如旧的 `category`）—— `forbidNonWhitelisted` 直接拒绝
  - `分钟周期的日期跨度不能超过 5 天`
- `401` - `访问令牌无效或已过期`（由守卫抛出）
- `429` - 触发全局限流（每 60 秒 60 次）
- `503` - CLI 不可用（二进制缺失，提示 `npm run setup:westock`）、输出格式变更导致缺列，
  或上游报错（如 `year` 传大 `limit` 触发 `service error`、请求过于频繁触发上游限流）
